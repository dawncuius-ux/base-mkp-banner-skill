# Base MKP Banner_V1 使用介绍

这是一份给新手使用的说明文档。你可以把它复制到飞书文档中，作为团队内部的 MKP banner 生成指南。

## 1. 这个 skill 是做什么的？

`Base MKP Banner_V1` 是一个用于生成 MKP 产品 / 模版宣传 banner 的 Codex skill。

它适合用来快速生成这类横幅：

- 行业模版推广 banner
- 产品能力宣传 banner
- 模版专题 banner
- 运营活动中的轻量视觉素材

默认输出尺寸是 `720×240`，画面固定分为三层：

- 背景层：负责氛围、色调、光感。
- 左侧 copy 层：放标题、副标题、CTA。
- 右侧 UI 层：展示产品界面或模版 UI 组合。

## 2. 最重要的一句话

右侧 UI 不能凭空画。

所有右侧 UI 组件都必须基于 Figma `组件` page 里的真实组件，或本地组件资产。可以改文案、字段、数据、行列，但不能新增源组件不存在的产品逻辑、按钮、筛选器、标题 icon 或工具栏。

PNG 草稿阶段，右侧 UI 必须使用 image 2.0 生成；Figma 组件只是产品真实性、结构、padding、字阶和内容槽位的参考约束。

## 3. 什么时候使用？

当你想要生成一张 MKP banner 时，可以使用这个 skill。

常见输入包括：

- `title`：主标题
- `subtitle`：副标题
- `CTA`：行动按钮文案，通常是“立即探索”
- 业务场景：比如零售门店、客服知识库、年中总结、制造业流水线等
- 模版列表：希望宣传的模版
- 可选组件：希望右侧 UI 使用哪些组件

## 6. 生成流程

一次标准生成通常分为 4 步。

### 第一步：理解 brief

Codex 会先判断：

- 这个 banner 面向什么行业或人群？
- 主要宣传什么模版？
- 右侧 UI 应该展示表格、看板、图表、进度还是指标？
- 哪几个 Figma 源组件最适合？

### 第二步：读取源组件

进入 image 2.0 生成前，必须完成这件事：

- 找到组件 node id 或本地源资产。
- 查看源组件截图。
- 写出组件契约。

组件契约包括：

- 固定结构：必须保留什么布局、控件、图表、padding、字阶。
- 可改槽位：哪些标题、字段、行数据、状态、数字可以替换。
- 禁止项：哪些按钮、icon、筛选器、工具栏不能新增。

### 第三步：生成 PNG 草稿

PNG 草稿阶段，右侧 UI 必须由 image 2.0 生成。

这一步重点看整体效果：

- 背景和 copy 是否和谐。
- 右侧 UI 是否真实可信。
- 信息密度是否合适。
- 是否只有一个视觉焦点。
- 文字有没有溢出、重叠、贴边。

### 第四步：写入 Figma

用户确认 PNG 后，才进入 Figma 终稿。

Figma 终稿需要：

- 创建 `720×240` frame。
- 顶层只有三层：`00-background`、`20-copy.zh-CN`、`10-ui.zh-CN`。
- 右侧 UI 克隆 Figma 源组件并改写可编辑槽位。
- 最终 UI 层必须可编辑，不能只是一张截图。

## 7. 红线标准

下面这些问题出现一个，就需要退回修改。

### 7.1 P0 红线

- 没有找到源组件就开始生成。
- 没有看源截图，只凭组件名想象 UI。
- 右侧 UI 是手工 HTML/SVG/Canvas/Sharp 拼出来的，而不是 image 2.0。
- 新增了源组件不存在的按钮、筛选器、标题 icon、右上角胶囊、工具栏。
- 把源组件结构换成另一种产品界面。

### 7.2 P1 问题

- 文案溢出、裁切、贴边。
- chip / pill / badge 装不下文字。
- 文字和图表重叠。
- 卡片 padding 和源组件明显不一致。
- 图表、头像、圆弧被拉伸变形。
- 多个大卡片同时抢视觉焦点。
- 支持卡遮挡主卡的关键结构。

## 8. 文案与字体规则

左侧 copy：

- 默认使用 `Noto Sans SC`。
- `720×240` 下标题字号固定为 `30px`。
- 副标题字号固定为 `14px`。
- CTA 字号固定为 `14px`。
- 不要为了避让右侧 UI 随意缩放左侧 copy。

右侧 UI：

- 不能继承左侧营销字体。
- 中文 UI 字体优先保留源组件字体角色。
- 大数字通常使用 `Roboto Bold`。
- 如果 Figma 无法加载某个字体，需要在结果中说明 fallback，不要静默变成 `Inter`。

## 9. 设计检查清单

生成后可以按下面清单检查：

- 尺寸是否是 `720×240`。
- 左侧 title、subtitle、CTA 是否和用户输入一致。
- 左侧 copy 是否使用背景对应的颜色。
- 右侧 UI 是否没有干扰左侧 copy。
- 是否只有一个视觉焦点。
- 每个右侧组件是否都有源组件。
- 是否没有新增源组件不存在的控件。
- 文字是否没有溢出、碰撞、贴边。
- 卡片 padding、行距、字号是否接近源组件。
- 图表、头像、圆弧是否没有变形。
- 投影色温是否和背景一致。
- 最终写入 Figma 时是否只有三层顶层 layer。

## 10. 常见错误

### 错误 1：把组件名当成设计指令

错误做法：

```text
画一个 M-Kanban 风格的客服看板。
```

正确做法：

```text
读取 Figma 组件 page 中 M-Kanban 的源截图，保留它的大白卡、顶部标题、头像/负责人胶囊行、三列线框卡片结构，只把内容改为客服工单场景。
```

### 错误 2：为了内容好看新增控件

例如给看板新增一个源组件没有的“今日生产线”筛选按钮。

这不允许。可以改内容，但不能新增产品逻辑。

### 错误 3：卡片旋转后内部对齐出问题

正确做法是先正面复刻组件，确认 padding、行距、文字容量都正确，再整体旋转卡片。

### 错误 4：右侧 UI 太复杂

一张 banner 只需要表达一个主视觉焦点。通常一个主卡 + 一到两个支持卡就够了。
