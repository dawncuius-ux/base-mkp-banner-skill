# Base MKP Banner_V1 使用说明

这篇文档给第一次使用 `Base MKP Banner_V1` 的同学看。你只需要理解：它是一个帮你生成 MKP 产品 / 模版宣传 banner 的 Codex skill，适合先出 PNG 草稿，再按确认效果写入 Figma。

## 1. Base MKP Banner 是什么？

`Base MKP Banner_V1` 用来生成 MKP 产品 / 模版宣传 banner。

默认输出：

- 尺寸：`720×240`
- 结构：背景层、左侧 copy 层、右侧 UI 层
- 草稿：先生成 PNG
- 终稿：确认后可写入 Figma，右侧 UI 层可编辑

适合的场景：

- 行业模版推广，比如零售、制造、客服、创业公司等
- 专题活动推广，比如年中总结、绩效考核、门店经营等
- 产品能力宣传，比如表格、看板、图表、进度、指标等

Skill 链接：

- GitHub：<https://github.com/dawncuius-ux/base-mkp-banner-skill>
- 本地安装后调用名：`$mkp-banner`

安装方式：

```bash
git clone https://github.com/dawncuius-ux/base-mkp-banner-skill.git
cp -R base-mkp-banner-skill/mkp-banner-skill ~/.codex/skills/
```

安装后重启 Codex，即可在 prompt 里使用 `$mkp-banner`。

1. 主卡：{主组件，可选}

- 右侧 UI 必须基于 Figma 里的源组件。

## 3. 工作流

使用这个 skill 时，一般按下面 5 步走。

### Step 1：给出 brief

你需要提供：

- 标题和副标题
- 要推广的模版
- 业务场景
- 期望使用的组件，如果你已经有想法

### Step 2：确认右侧 UI 组件来源

生成前，Codex 必须先确认右侧 UI 用哪些真实组件。

它会做三件事：

- 找到 Figma 组件 node id 或本地源资产
- 查看源组件截图
- 写出组件契约

组件契约会说明：

- 哪些结构必须保留
- 哪些文案和数据可以改
- 哪些控件不能新增

### Step 3：生成 PNG 草稿

PNG 草稿阶段，右侧 UI 必须用 image 2.0 生成。

这一阶段主要看：

- 整体视觉是否成立
- 左侧 copy 和背景是否和谐
- 右侧 UI 是否像真实产品
- 信息量是否合适
- 有没有文字溢出、重叠、变形

### Step 4：设计评审与修改

看到 PNG 后，可以直接指出问题，例如：

- “右侧 UI 信息太多，简化一下”
- “这个组件不够像源组件”
- “左侧 copy 颜色和背景不协调”
- “卡片 padding 不对”
- “这里文字溢出了”

Codex 会基于这些反馈重新生成或调整。

### Step 5：写入 Figma

确认 PNG 后，再写入 Figma。

Figma 终稿要求：

- 顶层只有三层：`00-background`、`20-copy.zh-CN`、`10-ui.zh-CN`
- 左侧 copy 独立可编辑
- 右侧 UI 层可编辑
- 右侧 UI 优先克隆 Figma 源组件，而不是重新手画相似组件

## 4. 可能出现的问题，以及如何修复

| 问题 | 表现 | 修复方式 |
| --- | --- | --- |
| 组件像是凭空画的 | 出现源组件里没有的按钮、icon、筛选器、工具栏 | 退回到源组件截图，重新写组件契约；禁止新增源组件不存在的控件 |
| 组件不够像原设计 | padding、行距、字号、图表位置和源组件不同 | 先查看源截图，再按源组件的结构和间距重做 |
| 信息太多 | 右侧堆了太多表格、卡片或数字 | 保留一个主视觉焦点，减少行列、缩短文案、删除次要卡片 |
| 文字溢出 | chip、pill、表格单元格装不下文字 | 优先增大容器或缩短文案，不要压缩字体和 padding |
| 图表变形 | 圆环、仪表盘、头像被拉伸 | 按整体缩放组件，不要单独拉伸图表或图片 |
| 左侧 copy 和背景不协调 | 文字偏蓝黑，但背景偏暖；或文字太浅 | 使用 Figma「背景 & copy color」里的对应 copy 色 |
| 右侧 UI 遮挡左侧 copy | 画面左右冲突，呼吸感不足 | 缩小或右移 UI；必要时减少支持卡 |
| Figma 字体不对 | UI 文案变成 Inter，或字重不像源组件 | 写入前做字体审计；中文 copy 默认 Noto Sans SC；UI 字体尽量保留源组件角色 |
| Figma 文档权限问题 | 链接打开无权限或 bot 创建后不可编辑 | 用 `lark-cli --as user` 创建，或补充应用权限后再授权 |

最重要的红线：

- 没找到源组件，就不要生成右侧 UI。
- 没看源截图，就不要只凭组件名想象。
- PNG 草稿阶段，右侧 UI 必须用 image 2.0。
- 可以改内容，不能改产品界面逻辑。

## 5. 其他内容：想了解工作原理时再看

这部分不是使用前必须理解的内容。你只在需要排查问题、优化输出稳定性时再看。

### 为什么右侧 UI 要用 image 2.0？

因为 PNG 草稿需要的是整体视觉效果：背景、光感、卡片层次、UI 组合的氛围。image 2.0 更适合先给出一个完整视觉草稿。

但 image 2.0 不能自由发挥产品界面，所以必须用 Figma 源组件做约束。

### 什么是组件契约？

组件契约就是在生成前写清楚：

- 源组件是谁
- 哪些结构不能改
- 哪些内容可以改
- 哪些元素绝对不能新增

例如 `M-Kanban` 可以把“销售签约看板”改成“客服工单看板”，也可以改列内容；但不能新增源组件里没有的筛选按钮或标题 icon。

### 为什么最终 Figma 稿要重建可编辑 UI？

PNG 草稿只是视觉确认，不适合长期维护。最终 Figma 稿需要让设计师可以继续编辑，所以右侧 UI 应克隆 Figma 源组件，再改写可编辑文案和数据槽位。

### 默认设计规范

- 默认尺寸：`720×240`
- 左侧标题：`30px`
- 左侧副标题：`14px`
- CTA：`14px`
- 左侧中文字体：`Noto Sans SC`
- 背景、copy 色、卡片投影色温要一致
- 右侧 UI 只保留一个视觉焦点
